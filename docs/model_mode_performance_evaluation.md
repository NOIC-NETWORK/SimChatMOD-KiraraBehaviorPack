# Kirara 思考模式性能评估报告

## 一、评估概述

本报告旨在评估 Kirara AI 三种思考模式（低能耗模式、平衡模式、性能模式）在终端用户工作电脑上运行的可行性，重点关注不同硬件配置下的显存占用情况及潜在的显存溢出风险。

## 四、三种模式的实现逻辑与显存需求

### 4.1 低能耗模式 (low)

**实现逻辑**：
- 直接调用 InferenceEngine.generate()
- 使用默认参数：temperature=0.75, top_p=0.9, num_ctx=8192, num_predict=512
- 无额外思考层，单次模型调用

**显存需求**：
| 项目 | 估算值 |
|------|--------|
| 单个8B Q4模型权重 | ~5.5 GB |
| KV缓存(num_ctx=8192) | ~0.8 GB |
| 运行时开销 | ~0.5 GB |
| **总计** | **~6.8 GB** |

---

### 4.2 平衡模式 (balanced)

**实现逻辑**：
- 调用 InferenceEngine.generate() 时设置 enable_thinking=True
- 使用 ollama.chat API 并设置 chat_template_kwargs={"enable_thinking": True}
- 同样使用 num_ctx=8192, num_predict=512
- 单次模型调用，但提示词中包含深度思考标识符

**显存需求**：
| 项目 | 估算值 |
|------|--------|
| 单个8B Q4模型权重 | ~5.5 GB |
| KV缓存(num_ctx=8192) | ~0.8 GB |
| 深度思考额外开销 | ~0.3 GB |
| 运行时开销 | ~0.5 GB |
| **总计** | **~7.1 GB** |

---

### 4.3 性能模式 (performance)

**实现逻辑（三阶段处理）**：

```
Step 1 (Draft):     qwen2.5-8b (kiraraModelO) → 生成草稿
Step 2 (Reflect):   qwen2.5-8b (kiraraModelO) → 自我反思（最多3轮）
Step 3 (Polish):    llama-3.1-8b (kiraraModelC) → 润色输出
```

**关键发现**：Step1 和 Step2 使用**同一模型**(qwen2.5-8b)，只有 Step3 才切换到 llama-3.1-8b。因此性能模式仅需**一次模型切换**，而非三次。

**显存需求分析**：

#### 场景A：Ollama串行加载（OLLAMA_MAX_LOADED_MODELS=1，默认）
| 阶段 | 模型 | 显存占用 |
|------|------|----------|
| Step 1+2 | qwen2.5-8b | ~6.8 GB |
| Step 3 | llama-3.1-8b | ~6.8 GB |
| **峰值** | **单模型** | **~6.8 GB** |

**评估**：Ollama默认串行加载模型，先卸载前一个再加载下一个，8GB显存够用。

#### 场景B：Ollama并行加载（OLLAMA_MAX_LOADED_MODELS>1）
| 项目 | 估算值 |
|------|--------|
| qwen2.5-8b 模型权重 | ~5.5 GB |
| llama-3.1-8b 模型权重 | ~5.5 GB |
| 双模型KV缓存 | ~1.6 GB |
| 运行时开销 | ~1.0 GB |
| **总计** | **~13.6 GB** |

**评估**：13.6 GB > 8 GB，严重超出显存容量，必然导致显存溢出。

## 五、硬件配置分级建议

### 5.1 最低配置要求

| 项目 | 最低规格 |
|------|----------|
| GPU | NVIDIA GTX 1660 SUPER 6GB 或同等 |
| VRAM | 6GB |
| 内存 | 16GB |
| 推荐模式 | 低能耗模式 |

**评估**：
- 6GB显存仅能运行单个8B Q4模型（~6.8GB需求接近极限）
- 平衡模式可能不稳定
- 性能模式不可用

### 5.2 推荐配置

| 项目 | 推荐规格 |
|------|----------|
| GPU | NVIDIA RTX 3060/4060 12GB 或同等 |
| VRAM | 12GB |
| 内存 | 16GB+ |
| 推荐模式 | 低能耗/平衡模式 |

**评估**：
- 12GB显存可稳定运行所有模式
- 性能模式切换时有余量
- 整体体验流畅

### 5.3 高性能配置

| 项目 | 高性能规格 |
|------|----------|
| GPU | NVIDIA RTX 4070/5070 16GB+ 或同等 |
| VRAM | 16GB+ |
| 内存 | 32GB+ |
| 推荐模式 | 全部模式 |

**评估**：
- 16GB+显存可并行加载双模型
- 性能模式响应速度快
- 可考虑使用更高参数模型（13B+）

## 七、关键防护措施

### 7.1 设置 OLLAMA_MAX_LOADED_MODELS=1（首要措施）

```bash
# Windows PowerShell
$env:OLLAMA_MAX_LOADED_MODELS=1
ollama serve

# 或在启动脚本中添加
set OLLAMA_MAX_LOADED_MODELS=1
```

**作用**：强制Ollama串行加载模型，确保切换模型时先卸载旧模型再加载新模型，避免显存溢出。

### 7.2 降低上下文窗口

```python
options={
    "num_ctx": 4096,      # 降低到4096
    "num_predict": 512    # 降低输出长度
}
```

**效果**：
- KV缓存减少约50%（从~0.8GB降至~0.4GB）
- 单模型显存需求降至 ~6.4GB
- 在6GB显存机器上也能运行低能耗模式

### 7.3 前端硬件检测

建议在前端添加硬件检测功能：
- 根据显存容量自动推荐合适的模式
- 切换到性能模式时显示警告信息
- 低显存配置下禁用性能模式

## 八、结论

### 8.1 模式可用性总结

| 模式 | 6GB显存 | 8GB显存 | 12GB+显存 | 推荐程度 |
|------|---------|---------|-----------|----------|
| 低能耗模式 | ⚠️勉强可用 | ✅完全可用 | ✅完全可用 | ⭐⭐⭐⭐⭐ |
| 平衡模式 | ❌不可用 | ✅完全可用 | ✅完全可用 | ⭐⭐⭐⭐ |
| 性能模式 | ❌不可用 | ✅可用(需配置) | ✅完全可用 | ⭐⭐⭐ |

### 8.2 针对当前开发机(RTX 5060/8GB)的建议

1. **低能耗模式**：✅ 日常使用首选，显存空间充裕
2. **平衡模式**：✅ 完全可用，深度思考功能正常
3. **性能模式**：⚠️ 需配置 `OLLAMA_MAX_LOADED_MODELS=1` 后可用，但模型切换会有延迟

### 8.3 最终建议

1. **强制配置**：在部署脚本中添加 `OLLAMA_MAX_LOADED_MODELS=1`，防止并行加载导致显存溢出
2. **默认模式**：终端用户默认使用低能耗模式，平衡模式作为推荐选项
3. **性能模式提示**：切换到性能模式时显示"可能需要较长响应时间"的提示
4. **硬件检测**：在前端添加显存检测，根据配置推荐合适模式

### 9.2 KV缓存计算公式

```
KV缓存大小(GB) ≈ (num_ctx × num_layers × head_dim × 2) / 8 / 1024 / 1024 / 1024
```

对于8B模型(num_layers=32, head_dim=128)：
- num_ctx=4096: ~0.4 GB
- num_ctx=8192: ~0.8 GB
- num_ctx=16384: ~1.6 GB
